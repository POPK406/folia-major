Three independent sub-tools under `dev/`, each self-contained and not imported by production code:

- `mcp/ts-code-map/` — Node MCP server (`server.mjs`) that spawns the native `tsc --lsp -stdio` process (from `@typescript/typescript-*` already installed in the repo) and exposes ten tools (`tools/*.mjs`: search, find_symbol, file_outline, inspect_symbol, references, callHierarchy/callers/callees, dependencyGraph, impact, changeContext). `codemap.mjs` builds a git-tracked module graph via `graph/modules.mjs`; `files.mjs` + `resolve.mjs` keep the LSP document cache in sync with mtime; `format.mjs` compresses raw LSP JSON into compact output; `cli.mjs` is the agent-facing entry point; `smoke.mjs` runs all tools as a smoke test.
- `pinyin/commandPinyinPlugin.mjs` — Vite plugin exposing a virtual module `virtual:folia-command-pinyin`. It uses Vite's built-in `parseAst` to statically scan `src/i18n/locales/zh-CN.ts` and `src/components/command-palette/commands/*.ts`, collects CJK phrases, converts them to full pinyin / initials via `pinyinTerms.mjs`, and emits a deterministic dictionary object. Watched paths trigger HMR invalidation.
- `probes/` — Visual regression / interactive surface harness. `definition.ts` defines the `ProbeDefinition` shape (`id`, `title`, `description`, `Component`). `registry.ts` eagerly glob-imports every `*.probe.tsx` via `import.meta.glob` and deduplicates by `id`, producing `PROBES` and `PROBE_LIST`. Each `.probe.tsx` is a self-contained React component wired to real app stores/services with deterministic fixture data, mounted through `main.tsx` behind a `?probe=` URL query. The `lattice-performance/` subfolder is a standalone benchmark harness (Wall.tsx, strategies.ts, run.ts) using framer-motion motion values for perf measurement.

Dependency direction is one-way: probes import from `src/*` but nothing in `src` imports back; the MCP server only talks to the tsgo child process and the filesystem; the pinyin plugin only reads source files during build.
