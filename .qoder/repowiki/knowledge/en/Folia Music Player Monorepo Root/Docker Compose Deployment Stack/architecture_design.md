Three Compose manifests compose the stack: `compose.yaml` is the production release pulling prebuilt images from `${FOLIA_IMAGE_NAMESPACE}`, `compose.build.yaml` overlays local build definitions against the repo root (`../..` context) for smoke testing, and `compose.sync.yaml` runs only the Sync Server with its host-mounted data directory. Services are split across four Docker networks — `folia-edge` (gateway to host), `folia-internal` (internal-only bridge for gateway ↔ APIs/backend), `folia-egress` (APIs outbound to upstream music providers), and `folia-sync` (isolated Sync Server network). The gateway is an nginx image that renders `nginx.conf.template` at startup via `entrypoint.sh`, which normalizes `FOLIA_AI_PROVIDER` through `envsubst`; it proxies `/netease`, `/kugou`, `/qq` into internal services while exposing `/healthz`, `/api/healthz`, and `/runtime-config.js`. Each service container is `read_only` with a `tmpfs /tmp` and `security_opt: no-new-privileges:true`. Image recipes live under `images/` as multi-stage Dockerfiles (builder → runner) using `node:24-alpine` and `nginx:1.29-alpine`; per-service source trees under `backend/`, `netease-api/`, `kugou-api/`, `qq-api/`, `sync-server/` provide their own `package.json`/`entrypoint.sh`. Version pinning is driven by `VERSION` plus `.env` variables `FOLIA_STACK_VERSION` / `FOLIA_SYNC_VERSION`, and CI validation uses `scripts/smoke-test.sh` and `scripts/validate-version.sh`.
