Three parallel entry points share the same logical handlers:
- `api/` — Vercel frameworkless functions written in plain JS (`*.js`).
- `api-ts/` — TypeScript sources compiled by `tsconfig.json` (`target: ES2022`, `module: ESNext`, `outDir: ../api`) into the `api/` directory; each file exports a default `handler(req, res)` matching Vercel's function signature.
- `worker/` — Cloudflare Workers runtime with a single `index.ts` default export that dispatches on `request.url.pathname` (`/api/generate-theme`, `/api/generate-theme_openai`, `/api/lyric-proxy`, `/api/segment-lyrics`) and forwards everything under `/api/qq*` to `handleQq` from `qq.ts`.

Each handler is duplicated across `api/` (JS) and `api-ts/` (TS) for Vercel, while `worker/` re-implements them as native `Request`/`Response` handlers. The QQ music integration lives in `worker/qq.ts`, wrapping `@yakult-green-tea/qq-music-api/serverless` and exposing an optional Durable Object-backed QR channel (`qqQrChannel.ts`) behind an HMAC-derived channel name keyed off `QQ_SESSION_SECRET`. AI theme generation goes through `generate-theme.ts` (Gemini, via `@google/genai` with a typed response schema) or `generate-theme_openai.ts` (OpenAI), both feeding `shared/themeSanitizer.mjs` before returning a dual light/dark theme object. Dependency direction is one-way: worker → provider modules → external SDKs; no cross-imports between providers.
