本模块由若干职责单一的主进程脚本组成，按“第三方 API 接入 + 本地服务”两条线组织：

- 第三方 API 桥接层
  - `kugouApiBridge.cjs`：通过 `createKugouApiBridge` 封装 `kugoumusicapi`，维护设备 cookie、会话持久化（V1→V2 envelope）、登录态合并与渲染侧脱敏；依赖 `safeStorage` 加密存储。
  - `qqApiStartup.cjs`：`startQqApi` 动态 `require('@yakult-green-tea/qq-music-api')`，在 require 前注入 `PORT`/`QQ_AUTH_STATE_PATH` 等环境变量，等待 `listening` 事件后返回 server，并通过可选的 `configureAuthSessionRepository` 注入 `qqAuthSessionRepository.cjs`。
  - `qqAuthSessionRepository.cjs`：实现 QQ 服务端凭据的 `load/save` 接口，使用 V1 envelope + base64 + `safeStorage.encryptString` 持久化，Linux 下拒绝 `basic_text` 后端。
  - `neteaseApiStartup.cjs`：提供可重试的启动辅助（`retryStartupOperation`、`withTimeout`），负责刷新 xeapi 公钥与匿名 token，并通过 `withoutImplicitClientIp` 剥离默认 X-Real-IP 以避免扫码位置不匹配。
  - `neteaseLoginDiagnostics.cjs`：包装上游 request，仅记录登录相关 URI 的请求元数据（状态码、耗时、IP 头类型、deviceId 尾段、cookie 标记），用于生成可公开的诊断快照。

- 本地服务层
  - `stageApi.cjs`：基于 Node `http` + `ws` + `busboy` 自建 REST/WS 服务器，暴露歌词/媒体上传、播放控制、队列操作等端点，使用 Bearer token 鉴权，通过 IPC 向渲染进程广播 `stage-session-*` 事件。
  - `lyricApi.cjs`：轻量 `http.createServer`，仅监听 `127.0.0.1:port/v1/lyric`，对内部歌词模型做 `sanitizeLyricData` 后输出稳定结构。
  - `aiTextClient.cjs`：Provider 无关的 JSON 客户端，统一 OpenAI 兼容端点（含 DeepSeek）与 Gemini，支持结构化输出 (`json_schema`)、推理能力探测与降级、超时 AbortSignal，调用 `shared/openAICompatibleRequest.mjs` 完成实际 fetch。

依赖方向单向向外：本模块被上层 main 组装，自身只依赖 `electron-store`、`safeStorage`、`os`、`crypto`、`fs`、`http`、`ws`、`busboy` 以及共享的 `shared/*` 工具，不反向引用业务逻辑。
