测试代码按运行环境与目标分层组织：
- `test/component/`：基于 Playwright 的组件级断言，通过自定义 fixture 在页面初始化前注入 `localStorage` 种子（`i18nextLng=en`、`static_mode=true`、引导版本），确保 store 模块加载时读到确定性初始值。
- `test/ui/`：基于 Playwright 的端到端 UI 测试，复用 `ui/helpers/appFixtures.ts` 中的 `installBaseState` / `mockNeteaseApi` / `mockNavidromeApi` / `openApp`，统一注入 mock 数据、拦截网络请求、隐藏 canvas 以保证截图基线稳定。
- `test/unit/`：基于 Vitest 的纯函数/逻辑测试，目录结构与 `src/` 一一对应（automix、lyrics、lattice、visualizer、services、stores、hooks、mod-system 等），每个被测模块一个 `.test.ts` 文件。
- `test/helpers/appState.ts`：共享常量（从 `package.json` 读取 `APP_VERSION`、`GUIDE_VERSION_STORAGE_KEY`）与 `waitForAppMounted` 等待 splash 消失，被 component 与 ui 两层共用。
- `test/fixtures/folium-signature/official-fixture/`：Folium 插件签名测试用的 fixture（`folium.sig.json`、`mod.json`、`client.mjs`）。
- `test/manual/`：独立可运行的诊断/调试脚本（如 `lyric-audit`、`stage-client`、`wallpaper-watchdog-sim`、`netease_lyrics_cli` 等），不属于自动化测试流水线。
依赖方向单向：component → helpers；ui → component（间接通过 fixtures）→ helpers；unit 直接依赖 `src/` 源码；manual 脚本各自独立。
