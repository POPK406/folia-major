模块按用途拆成三个互不依赖的子目录：
- `dev/mcp/ts-code-map/`：独立的 Node.js MCP 服务端，以 `cli.mjs` 为入口，通过 `server.mjs` + `mcpClient.mjs` 启动 tsgo (`typescript@7`) 的原生 LSP 进程，在 `tools/` 下实现 search/find_symbol/file_outline/inspect_symbol/references/callers/callees/dependency_graph/impact/change_context 等工具；`graph/modules.mjs` 维护 import 依赖图，`lsp/client.mjs` 封装 LSP 协议握手与请求派发，`resolve.mjs` 负责文件解析与符号过滤，`format.mjs` 压缩 LSP 原始输出。
- `dev/pinyin/commandPinyinPlugin.mjs`：Vite 构建期插件，用 Vite 内置 `parseAst` 扫描 `src/i18n/locales/zh-CN.ts` 与 `src/components/command-palette/commands/*.ts`，生成虚拟模块 `virtual:folia-command-pinyin` 暴露 `PINYIN_BY_PHRASE` 字典，通过 `server.watcher` 监听源变更并触发 HMR full-reload。
- `dev/probes/`：React 组件探针画廊，`main.tsx` 是 Playwright component testing 的挂载入口，`registry.ts` 用 `import.meta.glob('./*.probe.tsx', { eager: true })` 自动发现所有探针并以 `ProbeDefinition` 类型注册，每个 `*.probe.tsx` 独立导出一个可挂载的组件；`definition.ts` 定义契约，`lattice-performance/` 子目录是带性能埋点的复杂探针示例。
依赖方向单向：probes 仅依赖应用源码与 React；pinyin 插件仅依赖 Vite AST API；mcp 子项目完全自包含，只读仓库源码并通过 tsgo LSP 获取语义信息。
