模块按职责拆分为四个独立子域，无内部依赖关系：
- `lyricSegmentationService.mjs` 是对外入口，根据 `env.AI_PROVIDER` 在 OpenAI 兼容 API 与 Gemini 之间路由，统一抛出带 HTTP status 的 `SegmentationRequestError`。
- `openAICompatibleRequest.mjs` 实现 provider 探测（`api.openai.com` / `deepseek.com` / generic）与基于能力缓存的请求体协商（自动降级 `response_format`、`thinking`、`max_tokens→max_completion_tokens`），被 `lyricSegmentationService` 复用。
- `lyricSegmentationPrompt.mjs` 集中所有提示词、JSON Schema（OpenAI `json_schema` 与 Gemini 自有的大写 `OBJECT` 方言）、重试阶梯 `REASONING_SUPPRESSION_ATTEMPTS` 以及 `parseSegmentationResponse`——后者通过 `realignSegmentsToText` 以原文切片而非字符串比较来容忍空白符差异，保证输出与输入字符级一致。
- `themeSanitizer.mjs` 提供 `sanitizeTheme` / `sanitizeDualTheme`，对颜色、字体、动画强度等字段做白名单校验并回退到内置 light/dark 双主题。
- `modelManifest.json` 声明 beat_this、htdemucs 与 Python runtime 的镜像源、sha256 与平台分发；`realecoReleaseMetadata.cjs` 与 `themeSanitizer.cjs` 是 Electron CommonJS 侧的等价副本，由测试断言 ESM/CJS 版本一致。
依赖方向单向：service → prompt + openAICompatibleRequest，sanitizer 与 manifest 不被其他文件引用，作为纯数据/工具被上层消费。
